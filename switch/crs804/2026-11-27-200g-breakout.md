# CRS804 + DGX Spark CX7: 200G breakout DACs (2026-11-27)

Cables: NADDOD Q2Q56-400G-CU1, 1 m passive DAC, QSFP56-DD 400G on the switch to 2x QSFP56 200G on the Sparks.

## Port map (LLDP, 2026-11-27)

| Spark | Switch port |
|---|---|
| spark1 | qsfp56-dd-1-1 |
| spark3 | qsfp56-dd-1-5 |
| spark4 | qsfp56-dd-2-1 |
| spark2 | qsfp56-dd-2-5 |

A breakout DAC puts a cage's second Spark on lane interface `-N-5`. That interface is not a bridge port by default,
and its MTU is 1500, so that Spark is cut off from the fabric until its port is configured like `-N-1`.

## Change

- Before: `crs804-pre-200g.rsc`. After: `crs804-200g-breakout.rsc`.
- `-1-5` and `-2-5`: l2mtu 9500, mtu 9000, bridge port (hw), `pfc=pfc-tc3 trust-l3=keep`.
- All four live ports: `egress-rate-queue3=200000000000`, so the PFC rate equals the 200G link rate.

## Measured RDMA write

`ib_write_bw -x 3 -F -q 4 -s 1048576 -D 6`, host memory, RoCE v2 GID 3.

| | half A (`rocep1s0f1`) | half B (`roceP2p1s0f1`) | both at once |
|---|---|---|---|
| after cable swap, before reboot | 12.8 Gb/s | 12.7 Gb/s | 26.5 Gb/s |
| after rebooting all four Sparks | 111.9 Gb/s | 111.9 Gb/s | 196.0 Gb/s |

The after-reboot numbers are the same for spark1→spark3, spark4→spark2 and spark3→spark2. Before the reboot the
links were clean: RS-FEC, zero CRC or FEC errors, zero RoCE retransmits, zero pause frames or ECN marks, and PCIe at
Gen5 x4. Only a bandwidth test showed the throttle. **Reboot the Sparks after any CX7 cable or speed change.**

Why, as the Inkling-2 recipe's `setup/host-check.sh` documents: a cable change makes the ConnectX driver re-probe the
NIC at run time, and a runtime re-probe caps transmit at ~13 Gb/s per PCIe half until reboot. The check flags a
`PCIe slot power` kernel line later than 120 s of uptime. After the reboot it reported no re-probe on all four Sparks.

## Lossless under incast

Test: three Sparks write into one Sparks's half at once (`ib_write_bw --tclass=106`, DSCP 26 → TC3).

- Throughput: 120.6 Gb/s in total, the one-half PCIe limit.
- Losses: none. The receiver saw zero out-of-sequence packets, and the senders saw zero retransmits or timeouts.
- PFC: active on both sides. The receiver sent ~19K prio-3 pauses, and each sender received ~131K.

With tclass 0 (best effort), the same incast is dropped in queue 1, so RoCE traffic must keep DSCP 26.

## Lane recipes on the 200G fabric

All 14 lanes registered in `ops/spark-lane` were audited for fabric settings.

| Lanes | Status at 200G |
|---|---|
| `inkling2-tp4` | **Was blocked: fixed.** `models/inkling2-tp4/our-sparks.conf` pinned `FABRIC_SPEED=100000`, and the recipe's preflight compares it exactly with `/sys/class/net/<dev>/speed`, so the lane would not start. Now 200000; its host check passes on all 8 ports. |
| `ernie55-tf4`, `ernie55-tp4`, `dsv41-tf4`, `dsv41-tf4-ablit` | Pin both halves (`rocep1s0f1,roceP2p1s0f1`); no change needed. |
| `dsv41-native`, `glm53-tp3`, `glm53-tp4`, `glm53-tf2` | `scripts/nodes.sh` follows the route to a peer, then adds every active RoCE v2 device. No speed check; no change needed. |
| `glm53-gr8` | Both subnets through its own RDMA code; no speed constants. |
| `comfy-engine`, `comfy-studio-4x`, `studio-12`, `studio-2` | Single node, or SSH-only over the fabric. |
